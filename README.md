# kazspell

A Kazakh spellchecker built on the morphology the language actually has, rather
than on what a `.aff` file can express.

## Why this exists

Three Kazakh spellcheckers exist and none of them is good enough, measured on
the same harness:

| | catches misspellings | accepts real text |
|---|---|---|
| `kk_KZ` 2009 release | 99.4% | 82.1% |
| hunspell-kk v0.3.0 | 96.4% | 98.1% |
| apertium-kaz analyser | 98.7% | ~95.5% |

Nothing sits in the top-right corner, and each fails for a different reason.
The 2009 file allows one suffix per word. hunspell-kk knows 131,289 entries but
its affix rules are keyed on a phonological class — harmony plus a five-way
answer to *which consonant comes next* — which cannot say whether a morpheme
may attach at all, so a class hands every rule mined for it to every stem in it.
apertium-kaz has correct morphotactics, written by hand, and a 36.6k-stem
lexicon.

The target is **≥99% precision at ≥98% recall**: dominating all three at once.
It is reachable because correct morphotactics and a large lexicon have never
been put in the same system. Neither existing project can do it alone —
apertium's bottleneck is vocabulary, and vocabulary is what hunspell-kk has.

See `hunspell-kk/NOTES.md`, "The class flag is a phonological answer to a
morphotactic question", for the three measured attempts to reach this inside
the Hunspell format and why they failed.

## Design

A slot model, not a finite-state transducer. Kazakh suffixation is a fixed
template — көптік before тәуелдік before септік before жіктік; етіс before
болымсыздық before шақ before жіктік — so an analyser is a stem lookup, an
automaton over ordered slots, and the phonological realisation of each slot.
That is a few thousand lines of Rust with no C++ dependency, it compiles to
WebAssembly for npm and to a wheel for PyPI, and it keeps apertium-kaz as a
test oracle rather than a runtime dependency.

Hunspell and Nuspell remain a target, but as an *export*: once the model is
right, the `.aff` and `.dic` are generated by projecting it, which is also the
only way that dictionary stops being mined.

## Status

Phase 1, per-lexeme paradigm assignment. Every entry has to say which families
it takes; nothing downstream works until it does.

    tools/apertium_paradigms.py   lift 33,569 hand-assigned paradigms out of
                                  apertium-kaz's lexc, including the
                                  transitive/intransitive split that decides
                                  whether a passive can form at all

Coverage of hunspell-kk's 131,249 entries, and how far the sources agree:

| source | entries | share |
|---|---|---|
| apertium-kaz paradigms | 28,624 | 21.8% |
| kazdict POS labels | 45,737 | 34.8% |
| either | 64,146 | 48.9% |
| both | 10,215 | 7.8% |
| neither — needs corpus evidence | 67,103 | 51.1% |

Where both label the same entry they agree **91.8%** of the time. The 796
disagreements are 55% noun-against-adjective, which is the one boundary Kazakh
genuinely blurs, and only 84 are noun-against-verb, the distinction that
actually changes which track an entry inflects on.
